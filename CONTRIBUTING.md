# Contributing to jlt-commons

You do not need to be a member of this organization to help. Open an issue or a pull
request on any repo here and someone will look at it.

## The quickest ways to help

- **Fix something.** Open a pull request. For anything larger than a bug fix, open an issue
  first so nobody duplicates your work.
- **Report something.** Issues on the repo it affects.
- **Bring a project in.** See [proposing a project](https://github.com/jlt-commons/meta/blob/main/PROPOSING.md),
  then open an issue in [`meta`](https://github.com/jlt-commons/meta/issues).
- **Maintain a project.** When a project here needs a maintainer, say so in an issue
  in `meta` and it is usually yours.

## Pull requests

Each project sets its own review protocol and release cadence, so check the repo's own
README first. Absent anything more specific:

- Keep the change focused. One concern per pull request.
- Explain why in the description. The what is visible in the diff; the why is not.
- Add a test if the project has tests.
- Make sure the project's checks pass before asking for review.

We squash on merge unless a maintainer says otherwise, so do not worry about tidying your
commit history.

## Talking to people

Discussion happens on **#jolt** on the [Clojurians Slack](https://clojurians.net). It is a
shared channel with the wider Jolt community rather than a jlt-commons-only room, which is
deliberate: this community is small and does not need splitting up yet.

## Licensing

they arrived with. By contributing you agree your contribution is licensed under the terms
of the project you are contributing to.
